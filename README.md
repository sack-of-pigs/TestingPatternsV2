# Тестирование авторизации интернет-банка: REST Assured, Сериализация (Gson), Faker и Комбинаторный тест-дизайн

Продвинутый учебный проект, объединяющий практики API и UI автоматизации. Основной фокус проекта — тестирование функции входа в личный кабинет интернет-банка с использованием тестового API-режима для предварительного создания пользователей (SUT Setup). В коде реализована автоматическая сериализация Java-объектов в JSON через библиотеку **Gson**, паттерн **Data Generator**, а сценарии тестов построены на основе методов комбинаторики.

## 🎯 Цели и задачи проекта
* **Управление тестовым окружением через API**: программное создание учетных записей пользователей в базе данных банка (через POST-запросы API) перед выполнением UI-проверок авторизации.
* **Изучение сериализации объектов (Gson)**: автоматическое преобразование Java-классов данных (POJO/Data-классы) в формат JSON без ручного написания строк.
* **Комбинаторный тест-дизайн**: проектирование полного набора тест-кейсов на основе комбинаторики для проверки всех возможных состояний пользователя, валидности логинов и паролей.
* **Паттерн Data Generator & Lombok**: изоляция генерации случайных данных пользователей в утилитном классе с минимизацией шаблонного кода за счет аннотаций Lombok.
* **Оркестрация в CI**: конфигурация **GitHub Actions** для запуска SUT с передачей специфических аргументов командной строки (`-P:profile=test`).

## 🛠️ Развертывание окружения и тестовый профиль SUT

Тестируемая система (SUT) поставляется в виде скомпилированного Java-артефакта `app-ibank.jar` и находится в каталоге `artifacts/` проекта.

### 1. Управление артефактом в Git
Индексация бинарного файла выполнена принудительно для обхода правил глобального `.gitignore`:
```bash
git add -f artifacts/app-ibank.jar
```

### 2. Запуск в специальном тестовом режиме
Для открытия программного API, позволяющего создавать клиентов банка на лету, сервер необходимо запускать строго с флагом профиля:
```bash
java -jar ./artifacts/app-ibank.jar -P:profile=test
```
После старта приложение будет ожидать запросы на порту `9999`. Данная строка запуска также успешно интегрирована в конвейер автоматизации **GitHub Actions** (`gradle.yml`).

## 🧠 Архитектура решения и проектирование данных

В проекте реализован чистый подход к управлению данными без жесткого кодирования (хардкода) в тестах.

### 1. Сериализация и Data-классы (Gson + Lombok)
Для описания структуры пользователя создан дата-класс `AuthInfo`, снабженный Lombok-аннотациями `@Value`. При отправке HTTP-запроса через **REST Assured** встроенный плагин **Gson** автоматически превращает объект этого класса в валидное тело JSON-запроса.

### 2. Класс-генератор данных
Создан утилитный класс `DataGenerator`, предоставляющий методы для сборки случайных пользователей (активных или заблокированных) с помощью библиотеки `Faker`. 

**Ключевая особенность схемы**: Генератор не просто собирает объект в памяти Java, но и отправляет HTTP-запрос к API банка для сохранения этой записи в системе, после чего возвращает готового пользователя непосредственно в тестовый метод для выполнения UI-авторизации.

## 🧪 Комбинаторный тест-дизайн и покрытие тестами

Для всестороннего тестирования формы входа была применена техника составления комбинаций параметров (матрица состояний). В тестовом классе реализованы автотесты, проверяющие реакцию системы на следующие сценарии:

1. **Зарегистрированный активный пользователь** + валидный логин + валидный пароль ➡️ *Успешный вход*.
2. **Зарегистрированный заблокированный пользователь** + валидный логин + валидный пароль ➡️ *Ошибка: пользователь заблокирован*.
3. **Не зарегистрированный в системе пользователь** + случайный логин + случайный пароль ➡️ *Ошибка: неверный логин или пароль*.
4. **Зарегистрированный активный пользователь** + валидный логин + **НЕвалидный пароль** ➡️ *Ошибка: неверный логин или пароль*.
5. **Зарегистрированный активный пользователь** + **НЕвалидный логин** + валидный пароль ➡️ *Ошибка: неверный логин или пароль*.

Для локального запуска всего пакета тестов выполните команду:
```bash
./gradlew test -Dselenide.headless=true
```
*Сборка гарантированно завершается со статусом `BUILD SUCCESS` как локально, так и в облачном CI.*

## 📦 Стек технологий и конфигурация (`build.gradle`)
* **Язык программирования**: Java
* **Система сборки**: Gradle
* **Инструмент автоматизации CI**: GitHub Actions (с запуском SUT под профилем `test`)
* **Ключевые зависимости**:
  * `io.rest-assured:rest-assured` — отправка API-запросов для создания пользователей.
  * `com.google.code.gson:gson` — библиотека сериализации объектов в JSON.
  * `com.codeborne:selenide` — UI-автоматизация тестирования формы входа.
  * `com.github.javafaker:javafaker` — генерация случайных строк авторизации.
  * `org.projectlombok:lombok` — исключение boilerplate-кода.
